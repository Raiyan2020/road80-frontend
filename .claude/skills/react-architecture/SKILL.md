# React Architecture (road-80)

The goal of this skill is to prevent the single most common failure mode: a
component that fetches, transforms, validates, holds state, and renders 900 lines
of JSX all at once.

## The layering rule

```
Component            ← renders. props + local UI state only.
    ↓
custom hook          ← features/<f>/hooks/  — composes query + derived state
    ↓
TanStack Query       ← useQuery / useMutation, cache + invalidation
    ↓
service              ← features/<f>/services/<f>.service.ts — one fn per endpoint
    ↓
lib/api-client.ts    ← auth, language, force-logout, FormData handling
    ↓
Laravel backend
```

**Each layer may only call the one below it.** A component that imports
`api-client` directly has skipped three layers — that is the review trigger.

## Directory map

There is **no `src/`**. The app root *is* the source root, with `@/` aliased to it.

```
routes/       file-based TanStack Router routes → generates routeTree.gen.ts
features/     per-feature slices (home, explore, post-ad, auth, listing-detail, …)
  <feature>/
    components/   feature-owned UI
    hooks/        useX() composing queries + derived state
    services/     <feature>.service.ts — HTTP calls only
    schemas/      *.schema.ts — Zod
components/   shared/legacy presentational components
shared/       cross-feature hooks, services, types, utils, constants
lib/          api-client, api-base-url, query-client, firebase.config, bridge
stores/       zustand — *.store.ts
i18n/         translation layer + RTL direction
```

**Where does it go?** Used by one feature → `features/<f>/`. Used by two or more →
`shared/`. Infrastructure with no feature meaning → `lib/`.

## Service layer

A service function does one thing: call one endpoint and return the parsed body.
No React, no caching, no toasts, no state.

```ts
// features/listing-detail/services/listing-detail.service.ts
export const listingDetailService = {
  getListing: (id: string) => api.get<ListingResponse>(`/v1/listings/${id}`),
  toggleFavorite: (id: string) => api.post(`/v1/listings/${id}/favorite`),
};
```

Follow the existing naming: an exported object named `<feature>Service`, methods
named for the action. See `shared/services/social-platforms.service.ts`.

## Hook layer

Hooks own the query wiring and any derived state, so components stay declarative:

```ts
export function useListing(id: string) {
  const query = useQuery({
    queryKey: ['listing', id],
    queryFn: () => listingDetailService.getListing(id),
  });
  return { ...query, isSold: query.data?.data.status === 'sold' };
}
```

## Component layer

A component should read top-to-bottom as markup. If you find yourself writing
`useEffect` with a fetch, `.map()` chains transforming API shapes, or business
rules inline — that logic belongs in the hook or service.

Practical ceiling: if a component passes **~200 lines**, or holds more than
**3–4 `useState`s**, split it. Extract sub-components into the same
`features/<f>/components/` folder.

## ⚠️ Known structural debt

Three real traps in this repo. Do not extend any of them:

1. **`utils/api-client.ts` is a dead stale fork.** Zero importers (vs 25 for
   `lib/api-client.ts`). It reads only the legacy flat `user.token`, missing the
   Zustand-persist format, and it has **no 401 / force-logout handling**.
   Importing it would silently break auth. Delete it; never import it.
2. **`App.tsx` is dead code.** Nothing imports it. It is a pre-router hash-routing
   shell. Real routing lives in `routes/` and `routes/__root.tsx`.
3. **`components/` vs `features/*/components/` overlap.** New feature UI goes in
   the feature folder. `components/` is legacy — do not grow it.

## Never hand-edit

`routeTree.gen.ts` is regenerated by `TanStackRouterVite` from `routes/`. Edit the
route files instead.

## Checklist

- [ ] Component contains no `fetch`/`api` import
- [ ] HTTP call lives in a `*.service.ts`
- [ ] Query/mutation wiring lives in a hook, not the component
- [ ] File placed by scope: feature-local vs `shared/` vs `lib/`
- [ ] Not importing `utils/api-client.ts` or `App.tsx`
- [ ] `routeTree.gen.ts` untouched
